# Add the Duality Lab logo to the MAGE site header

**For:** the owner of `davisjam/model-based-agentic-software-engineering`
**Goal:** a visitor at the top-left of any MAGE page can reach James Davis's
homepage. Today the top-left is the MAGE wordmark, which links back to the MAGE
landing — so there is no route out of the project site.

---

## Where the logo lives, and why you must not copy it

Canonical file — the only copy:

    repo:  davisjam/davisjam.github.io    images/logo.svg
    live:  https://davisjam.github.io/images/logo.svg

It is an SVG, `viewBox="0 0 1160 380"` (a wide wordmark, roughly 3:1), 3.8 KB,
in Purdue Aged Gold `#C0A062` on `#1a1a1a`.

**Reference it, do not vendor it.** Both sites are served from the *same
GitHub Pages origin*: the homepage at `davisjam.github.io/` and MAGE at
`davisjam.github.io/model-based-agentic-software-engineering/`. A root-absolute
path therefore resolves across both:

    /images/logo.svg

That is genuine single-sourcing — one file, one deploy, no sync step. Copying
the SVG into this repo would create a second surface that silently drifts the
first time the logo is revised, and the drift is invisible because a stale logo
still renders perfectly.

Root-absolute also survives page depth. `index.html` uses relative hrefs, so a
copied-in asset would need `rel_root` threading for sub-pages; `/images/...`
needs none.

**The one caveat:** this holds only while MAGE is served under the
`davisjam.github.io` origin. If it ever moves to its own domain, switch to the
absolute `https://davisjam.github.io/images/logo.svg`, which costs a
cross-origin request but keeps a single source. Do not solve it by copying.

## How many headers this site has — measured, not guessed

More than two. I applied each step, ran `catalog.py build`, and counted the
HTML files carrying the link:

    Step 1 only (landing nav)        1 of 237
    Steps 1 + 2 (nav + crumb)      106 of 237

So the two steps below get you to 106. The remaining 131 files come from other
emitters, listed at the end. Decide deliberately how far you want to go; do not
assume `build` covers the site.

  * `_v3_nav()` (~line 2754) — the grouped nav with the MAGE wordmark. Exactly
    ONE call site, line 4492: the landing page. **Step 1.**
  * `_page()` / `_crumb()` (~line 2102 / 2111) — `theory.html`,
    `quick-start.html`, the entry pages. Emits
    `<nav class="crumb"><a href="index.html">Home</a> / Title</nav>`. **Step 2.**

Anyone arriving on a deep page from a search engine lands on a `_page()` page,
so Step 2 is the one that actually serves the goal. Step 1 alone looks right
to whoever checks the landing page and helps nobody else.

## Step 1 — the landing page

`index.html` is generated — its second line says so:

    <!-- GENERATED by catalog.py build — DO NOT EDIT. -->

Edit the generator, then rebuild. The nav is emitted by `_v3_nav()` in
`catalog.py` (~line 2752). Currently the first child of `<nav class="v3-nav">`
is `<a class="v3-nav-home" href="index.html">` — mortarboard glyph plus the
word MAGE.

Add the lab logo as a NEW first child, before that link:

    '<nav class="v3-nav" aria-label="Primary">\n'
    '  <a class="v3-nav-lab" href="https://davisjam.github.io/">'
    '<img src="https://davisjam.github.io/images/logo.svg" alt="Duality Lab — James C. Davis" '
    'width="116" height="38"></a>\n'
    '  <a class="v3-nav-home" href="index.html">'      # unchanged from here
    ...

and a rule alongside the other `.v3-nav-*` rules (~line 2371):

    .v3-nav-lab { flex:0 0 auto; display:inline-flex; align-items:center;
                  margin-right:14px; }
    .v3-nav-lab img { display:block; height:38px; width:auto; }

## Step 2 — every other page

`_page()` (~line 2102) assembles `<body>\n<main>\n{crumb}...`. Put the same
link above the crumb, smaller: the crumb is a light meta line and a 38px logo
would overpower it.

    f"<main>\n"
    f'<a class="v3-nav-lab v3-nav-lab--crumb" href="https://davisjam.github.io/">'
    f'<img src="https://davisjam.github.io/images/logo.svg" alt="Duality Lab \u2014 James C. Davis" '
    f'width="76" height="25"></a>\n'
    f"{crumb}\n{sub}{body}\n..."

with, alongside the Step-1 rule:

    .v3-nav-lab--crumb { margin: 0 0 10px; }
    .v3-nav-lab--crumb img { height: 25px; }

`_page()` takes a `rel_root` for its other assets, but this link needs none —
that is the point of the root-absolute path, and it is why the same string
works from both headers at any depth.

Then:

    python3 catalog.py build

and commit the regenerated HTML together with the `catalog.py` change — the
build touches many pages, so keep them in one commit.

### Why these specific choices

- **`width`/`height` on the `<img>`.** The intrinsic size is 1160×380; without
  explicit dimensions the browser reserves no space and the nav reflows when
  the SVG arrives. 116×38 preserves the ratio exactly at 1/10 scale.
- **Real `alt` text, not `aria-hidden`.** This link's only content is the
  image, so the alt text IS the link's accessible name. An empty alt would
  leave a nameless link — a WCAG 2.4.4 / 4.1.2 failure. The MAGE wordmark link
  beside it is safe with `aria-hidden` on its glyph precisely because it also
  carries the text "MAGE".
- **`alt` names the destination, not the picture.** "Duality Lab — James C.
  Davis" tells a screen-reader user where the link goes. "Logo" would not.
- **A separate link, not a wrapper around the existing one.** Two destinations
  need two links; nesting them would be invalid HTML and untabbable.

## Check it worked

Both steps are verified. I applied them, ran `catalog.py build` (122 chapter
pages + 93 entry pages + landing, no errors), and confirmed: the rendered
markup on the landing with the logo preceding the MAGE wordmark inside
`<nav class="v3-nav">`; the crumb variant on `theory.html`; and the file count
of 106. The repo was returned to 1dfca7ef, clean — nothing of mine is in it.

1. `https://davisjam.github.io/model-based-agentic-software-engineering/`
   shows the logo top-left, left of MAGE, and it navigates to the homepage.
2. The same holds on a sub-page (`theory.html`, `quick-start.html`). This is
   the step that catches the two-headers trap: with only Step 1 applied,
   `grep -rl v3-nav-lab --include='*.html' .` returns exactly 1. With both, it
   should return every generated page. Run that grep — it is the whole check.
3. At 375px wide the nav still wraps sanely; `.v3-nav` is already
   `flex-wrap:wrap`, and the logo is `flex:0 0 auto` so it will not squash.
4. Tab to the logo: focus is visible and a screen reader announces
   "Duality Lab — James C. Davis, link".

## The other 131 files

Not covered by Steps 1-2. Each has its own `<body>` emitter:

    catalog.py:3976                        catalogue-views.html
    book/build_book.py:2957                the 122 book chapter pages
    book-models/render_models_view.py:152  the models view
    book/build_visual_aids.py:212          visual aids

Separately, files under `agent/` carry the `GENERATED by catalog.py build`
banner yet did not change when I ran `build` — so they are produced by a
different subcommand, or are committed artifacts of an older run. Worth
resolving on its own merits: a page claiming a generator that no longer
regenerates it is stale-by-construction, and that is a bigger problem than
the logo.

My recommendation: do Steps 1-2 now, since together they cover the landing
and every page a visitor is likely to arrive on. Treat the book chapters as a
second decision — they are a bound artifact with their own identity, and a lab
logo may not belong in a book's running header at all.

Cheap automated check, if you run axe on this site:

    the nav must contain exactly two links whose href leaves the MAGE site
    (the lab logo and the GitHub icon), and every link must have a
    non-empty accessible name.
